# 敏感词管理和词库迁移

基线：dev / 4be7b7a。方案经用户确认：独立 MySQL + Redis、内部管理 API、通用风险规则。
从 hk-ai-tutor 的 agent 管理 API 一次性导出分类与词条，复制到本地后独立维护。
不连接对方数据库、不修改对方词库、不定期同步。源地址与令牌在运行导出命令时配置。

## 实施约定

- 数据源 csv（默认）或 mysql；保留现有 NFKC/casefold、CSV 热加载、SSE 契约。
- 分类、词条启停及软删除；有效词由 agent 场景内两层启用状态共同决定。
- 独立 MySQL 连接。显式执行 SQL 迁移，应用启动不自动建表。
- Redis 快照带单调版本，事务提交后刷新；旧快照不能覆盖新版本。
- Redis 故障使用进程最后有效词库；冷启动可从 MySQL 加载，两者均失败则启动失败。
- 管理 API 同时校验网关令牌和独立管理密钥；未配置密钥时拒绝管理访问。
- 自伤关怀优先，随后词库拦截和辱骂/人身攻击请求规则；不复制校园和政治规则。
- 命中后不调用 Agent/工具、不保存问答或地图上下文、不记录原始问题。
- 导出保留分类关联和启停状态，完整校验后原子写快照；导入按来源 ID 幂等，不覆盖本地编辑。

## 工作拆分

1. Repository、SQL migration、Redis cache 与实际隔离数据库测试。
2. 管理 API、鉴权、请求模型与接口测试。
3. 源 API 导出、导入 CLI 与 HTTP fixture 测试。
4. 配置、统一运行时、风险规则、聊天接入和文档。

## 接口检查

| 生产者 / 消费者 | 约定 |
|---|---|
| 存储 / 缓存 | load_snapshot(scope) 返回 scope/version/words |
| 存储 / 管理 | CRUD 返回 item/version；导入返回统计/version |
| 导出 / 导入 | schema_version=1，来源 ID 关联分类与词条 |
| 运行时 / 管理、聊天 | check 返回 action/reason/rule_id/hit_words/version/reply |

## 验证与已知基线

原始 142 个测试中有 1 个既有失败：test_keeps_fly_to_marker_after_area_station_rendering。
预期 5 个地图动作，实际 2 个；本次不扩大范围修改地图行为。
需要验证分页异常、导入幂等、事务回滚、场景隔离、并发缓存发布、冷启动失败及聊天回归。

2026-09-04 实施验证结果：

- MySQL 8.4 和 Redis 7 隔离容器下，敏感词及聊天/API/配置/SSE 相关 86 项测试全部通过。
- 全量 198 项：197 通过，上述既有地图测试仍失败；组合运行还有事件循环未关闭的 ResourceWarning。
- 验证了真实存储 CRUD、跨运行时缓存更新、故障降级、提交成功但发布失败、锁等待超时和取消后恢复。

- Python 编译检查、Git 空白检查、已安装依赖兼容检查通过。
