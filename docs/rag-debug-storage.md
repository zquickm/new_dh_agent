# 知识库检索调试数据

检索调试数据写入现有 `agent_run_event`，不新增表、字段、索引或迁移。
仅新运行可以采集，旧记录不能补回。检索、排序和筛选规则不变。

## 保存协议（schema_version = 1）

- `event_type=rag_debug`：阶段清单，记录 capture_id、stage、tool_call_id、round_number、request_id、attempt、knowledge_id、大小、SHA256 和完整性。
- `event_type=rag_debug_part`：大内容分片，payload 保存 capture_id、part_index、part_count、text。
- 普元响应始终分片保存；其他阶段序列化后超过 24000 字符也分片。
- 所有分片成功写入后才写完整清单；失败或取消尝试写入不完整标记，取消继续向上传播。
- SHA256 基于 UTF-8、按键排序的 JSON，兼容 MySQL JSON 调整对象键顺序。响应保存完整 JSON 正文，非 JSON 响应保存完整文本；JSON 空白及键顺序不作为 HTTP 原始字节保留。
- Authorization、Cookie、密码、API Key 等敏感字段脱敏，不保存请求鉴权头。

阶段如下：

1. query：原始问题、模型检索问题、同义词扩展后的实际问题、基础及选中场景、当次阈值、标签、知识库参数。
2. request：每次实际请求参数、请求编号、尝试次数、超时与重试配置。
3. response：每次 HTTP 响应状态、耗时、完整响应正文（含筛选前候选，保持数组顺序）。
4. request_error：请求错误类型、取消状态及是否将重试。
5. parse：原始候选序号、解析后序号，标记空文本/非法候选、超出召回数量等原因。
6. sort：原始序号、排序后序号、时间标签和实际排序规则。当前 search_all 路径不执行重排，明确保存 rerank_executed=false。
7. filter：当次本地阈值、保留数量，逐条记录保留、低于阈值或超出数量，以及最终位置。
8. result：最终检索结果、片段正文和来源。
9. sources：检索结果与引用缓冲区编号的映射。
10. tool_end：单次工具成功、失败或取消状态。
11. answer：最终回答明确引用的知识来源，排除自动附加的数据库来源；未引用不意味着模型未使用。
12. run_end：运行采集结束标记及此前保存失败数量。业务状态以运行记录为准。

## 权限和查询

调试回调使用任务局部上下文，不写入模型上下文、不进入实时事件发送器。
普通用户重放在 SQL 分页前排除上述两类事件；管理员事件列表仅返回阶段清单，隐藏原始分片。

沿用管理员对话接口前缀：

`GET /admin/conversations/{conversation_id}/runs/{run_id}/rag-debug/{capture_id}`

该接口按需重组内容并校验分片数量、字节数与 SHA256；记录不匹配会话或运行返回 404。
管理员鉴权沿用可信 Gateway 身份及 ADMIN 校验。普通用户不能获取调试内容。

管理后台“知识库检索链路”按调用分组，原始响应和大阶段按需读取，显示筛选明细和缺失提示。
事件分页未加载完时，页面提示继续加载，不把当前页误当作完整链路。

## 故障语义

调试数据写入失败不改变业务检索结果；后续阶段携带此前失败数量，并尝试保存失败标记。
数据库完全不可用或进程被强制终止时不能保证失败标记入库，需结合服务日志和缺失阶段排查。
运行取消、请求失败时保留已成功提交的阶段，不把缺失内容展示为完整记录。
