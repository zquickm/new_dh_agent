# 空间联动

本 Skill 范围内的空间要素位置、基础属性和分布使用 `spatial_query_service` 的通用查询。本 Skill 独立完成空间检索、观测站查询和地图联动。`spatial_query_service` 只返回数据；查询结果的标点、线面展示、定位和清图均调用 `map_action` 完成。参数以工具 Schema 为准。

下文的目录、字段定义、空间查询和观测查询操作均通过 `spatial_query_service(operation=操作名, ...)` 调用，不是独立工具。取得真实查询结果后，由助手组装标点及 `popup_content`，再调用 `map_action`；查询服务不会自动绘图或补齐弹窗。

## 对象与范围

- 本轮明确指定的对象或范围优先；连续追问继承最近明确对象。用户未指定其他地点时，选区内“有哪些”、空间分布和类型筛选默认使用当前选区；明确查询本轮新选区时，不因提到地点名就清除选区。“它”“这个站点”无法唯一对应时请用户明确，不回退为整个选区查询。
- 区域追问和类型筛选沿用本轮提供的有效 `selected_area`，不从历史恢复旧选区。切换地点后不再套用旧选区，也不主动复述无关范围或历史结果。不默认全库查询、不猜测坐标或半径。
- 明确地名的问题（如“杭州湾有哪些观测站点”）无需用户先框选：依据当前类别字段定义中确实支持的区域归属字段及合法值过滤，或使用已取得且对应目标区域的可靠边界做空间查询。不以站名包含地名代替区域归属，不把中心点当作区域边界；无法确定可靠区域条件时再请用户明确范围或框选。
- 完整使用选区几何，不用外接矩形替代多边形，不扩大或改写范围。通用查询传 `query.spatial=selected_area.spatial`。坐标为 EPSG:4490，经纬度数组顺序为 `[经度, 纬度]`，距离单位为米。
- 存在有效选区时，用户改问其他地点、无关问题或明确取消选区，先单独调用 `map_action(action_type="CLEAR", payload={}, clear_selection=true)`，收到结果后再处理新问题。`clear_selection` 是顶层参数；没有有效选区不重复清除。本轮新框选区域、选区内单站追问及单纯清理标记均不触发取消选区。

## 空间要素查询

- 明确查询调查断面、测点或辅助点的位置、属性及观测分析时，由主助手选择对应业务 Skill，使用 `database_query`；本 Skill 不承接该类专项查询，也不互相加载其他 Skill。区域泛问“有哪些要素”仍按目录查询全部类别，包括断面空间记录；这些记录只用于空间总览和分布展示，不能作为历史观测或统计依据。
- 区域内泛问“有哪些”时，用 `list_spatial_elements` 发现目录，再按返回的 `dataKey` 逐类调用 `query_spatial_element`，不默认只查观测站，不因要素类别不同而跳过查询。逐类汇总实际命中数量和名称；按类别解释记录数量，不混淆不同对象的统计口径。已明确类别时只查目标类别；目录仅表示可查询的类别，不表示区域内实际存在。
- 区域总览由本 Skill 独立完成；查询命中的全部类别纳入回答，再调用 `map_action` 展示实际取得的几何，不追加其他业务流程或专题图。
- `list_spatial_elements` 是类别目录，`get_spatial_element_detail` 是类别字段定义，不是单个要素的详情；具体要素记录使用 `query_spatial_element`。
- 某类别查询失败或不支持所需空间关系时，说明该类未完成查询，不当成不存在，也不改成无范围的属性查询。
- 通用区域查询完整使用当前选区的空间条件；需要地图展示时请求返回几何。普通区域总览优先省略 `query.fields`，使用服务默认字段；默认字段满足需求时直接查询，不为精简返回值额外自选字段或获取字段定义。确需自选 `fields`、`conditions` 或 `orderBy` 时，复用当前类别的字段定义，缺少定义才调用 `get_spatial_element_detail`；分别确认字段可用于返回、过滤或排序，不套用其他类别的字段，不猜测字段名、类型或枚举。
- 收到“字段不可查询”等字段校验错误时，先调用 `get_spatial_element_detail` 核对该类别的最新定义，确认允许后再修正，不更换猜测的字段名连续尝试。仅返回字段选择有误且默认字段可满足需求时，可省略 `fields`；保留原有空间范围和用户要求的过滤、排序条件。定义仍无法支持需求时说明限制，不删除条件绕过校验。
- 仅计数且不展示地图时无需几何；需要地图展示时保留完整几何，已有几何坐标时不额外请求重复的经纬度属性。用户明确要求详情或其他属性时按需查询，不遗漏用户所需数据；后续同类分页复用已确认的字段定义。
- 观测站的位置、基础详情、名称和类型筛选也走通用查询，按目录选择对应要素。区域内筛选保留空间条件，将类型等要求加入属性条件；类型编码依据字段的枚举与中文标签，不维护另一套站点查询路径。
- 同阶段互不依赖的查询在同一轮提交；依赖目录、字段定义或前一步结果的调用，等待实际返回后再执行。

## 观测站业务查询

观测站基础记录使用上述通用查询；在线状态和观测数据使用同一个 `spatial_query_service` 的以下操作，仅适用于接口支持的业务观测站。目录属性中的运行状态不等同于实时在线状态，空间记录也不代表观测时序数据。

| 需求 | `spatial_query_service` 的 `operation`（所需参数） |
| --- | --- |
| 在线状态 | `station_status`（`tznos`） |
| 最新观测 | `observation_summary`（`tzno`） |
| 最近若干小时的要素变化 | `observation_trend`（`tzno`、`element`、`hours`） |
| 明确起止时间内的观测 | `observation_range`（`tzno`、`data_type`、`start_time`、`end_time`） |

- 已有可信且对应当前目标的 `tzno` 时直接查询。只有站名时，按字段定义用 `query_spatial_element` 查询名称并取得站号；查基础详情则按真实标识过滤。选区内追问保留空间条件；明确独立查找某站时可按名称做属性查询，无需构造全球范围。内部候选不绘制；无匹配说明未找到，多个候选无法唯一确定时请用户选择，不任取首项、不擅改站名。
- 保留用户指定的时间和指标。相对小时趋势直接用 `hours`；“昨天”等日期需换算且缺少可靠当前时间时，先调用 `CurrentServerTime`，按返回时区解释。`data_type` 不能当作趋势 `element` 的通用别名。
- 当前不支持跨站批量比较或排名最新观测值，不编造操作或逐站拉取绕过限制；地图比较动作与站点位置不能作为观测值比较的依据。

## 地图联动

- “杭州湾有哪些观测站点”等指定地点或选区内的站点列表问题，默认同时需要文字列表和左侧地图标点，无需用户另说“地图展示”。查询时设置 `includeGeometry=true`，按后续分页规则取得结果后，使用真实点位调用 `map_action(action_type="MARKER_ADD", ...)`，再完成最终回答；不得查到有坐标的站点后仅返回文字。用户明确只要文字、查询无结果、缺少有效坐标或相同点位已展示时按对应规则处理。
- 面向用户的其他区域要素、位置和单站业务查询，也默认先取得数据，再显式调用 `map_action` 展示；用户明确只要文字时不绘图。内部查找候选不绘制。查询与依赖结果的绘图分轮执行，不提前编造点位。
- 点位使用 `MARKER_ADD`，线面使用 `GEOJSON_ADD`；使用真实标识、名称、坐标或完整 GeoJSON，不自行把点连成线。通用查询需要返回几何时设置 `includeGeometry=true`。
- 站点分布标点的 `markers` 每项保留真实 `id`、`name`、`coordinates`，以及查询结果中已有的 `type`、`status`；观测站已有真实站号时用站号作为 `id`，不改用临时序号。每个站点必须携带 `popup_content={"title":站点名称,"fields":[{"label":字段名称,"value":真实字段值}]}`，用于点击查看信息，无需用户另行要求。弹窗保留查询结果中已有的站号、类型、状态、所属区域、管理单位等站点信息，不为缩短参数删除详情，也不编造缺失值或将基础属性状态称为实时在线状态。顶层保留 `layer_id` 和所需的 `fit_bounds`；线面保留完整真实几何和属性。
- 每次通用查询只返回一页。需要完整展示时，保持范围、过滤和排序，按返回的条数补取后续页；取得全部点位后合并提交，避免重复调用覆盖前一页。数据未取全或部分几何缺失时只展示有效部分，并说明覆盖范围。
- 同一次区域查询的不同类别使用各自图层，保留当前选区和其他类别结果。替换旧结果只清除对应图层；成功查询为空时可清理该图层，查询失败时保留已有展示。不逐类别全局清图。
- 观测站的地图参数使用 `layer_id="observation-stations"`，这是前端图层标识，不是查询工具名；其他类别按稳定的类别标识分层。有有效选区时保持选区视野；同一对象已展示且位置、弹窗信息均未变化时无需重复清图标点。已有标点缺少弹窗信息时须用相同真实标识补齐，不能仅因位置未变而跳过。
- 单站详情、状态或时序追问需要地图展示时复用已有真实坐标；缺少坐标再用通用查询按站号获取几何，不用观测数值推测位置。定位、弹窗、表格等由 `map_action` 完成；没有坐标仍可回答已有数据。
- 地点切换时有可信坐标可调用 `FLY_TO`；它会清除旧站点和定位标记，因此在新结果标点前完成视角切换，避免清除刚绘制的结果。

## 结果解释

- 通用结果按目录中文名、`total` 和实际返回的 `features.properties` 汇总；不同目录可能重叠，不将数量相加作为去重总数。观测站基础记录使用相同结果结构，不根据站名重新分类或改写服务返回的数量。
- `total` 是匹配总数，`returned` 是本页记录数；只有取全并处理有效几何后才能说明提交了完整结果。页数、数量不一致或后续查询失败时说明限制，不把部分数据称为全部。
- 查询成功不等于地图已展示；只有调用 `map_action` 后才能说明已提交展示指令，没有前端渲染确认时不声称已显示。
- 仅成功查询的 `total=0` 表示无匹配；失败、未查或截断不等于不存在。空结果不自动放宽范围、类型或时间；失败只在参数可据已有信息纠正时重试，不擅换业务数据源。
- 在线状态与观测新鲜度分开解释，说明观测时间，“最新”不等于实时。趋势和区间数据有采样或条数限制时说明覆盖范围；缺失值不补零。数据可用但坐标缺失时回答已有数据，不承诺已定位。
