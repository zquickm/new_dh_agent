# 空间联动

空间要素的位置、基础属性和分布统一使用 `spatial_query_service` 的通用查询，包括断面及其测点。本 Skill 独立完成空间检索、观测站查询和地图联动。下文查询操作均通过 `spatial_query_service(operation=操作名, ...)` 调用；查询只返回数据，取得结果后再显式调用 `map_action` 标点、展示弹窗或线面。参数以工具 Schema 为准。

## 对象与范围

- 本轮明确指定的对象或范围优先；连续追问继承最近明确对象。用户未指定其他地点时，选区内“有哪些”、空间分布和类型筛选默认使用当前选区；明确查询本轮新选区时，不因提到地点名就清除选区。“它”“这个站点”无法唯一对应时请用户明确，不回退为整个选区查询。
- 区域追问和类型筛选沿用本轮提供的有效 `selected_area`，不从历史恢复旧选区。切换地点后不再套用旧选区，也不主动复述无关范围或历史结果。缺少明确空间范围时请用户提供位置或选区，不默认全库查询、不猜测坐标或半径。
- 明确地名（如“杭州湾有哪些观测站点”）时，可依据当前类别真实的区域归属字段及合法值过滤，或使用已取得的可靠区域边界查询；只有无法确定区域条件时才请用户明确范围，不以站名包含地名代替区域归属。
- 完整使用选区几何，不用外接矩形替代多边形，不扩大或改写范围。通用查询传 `query.spatial=selected_area.spatial`。坐标为 EPSG:4490，经纬度数组顺序为 `[经度, 纬度]`，距离单位为米。
- 存在有效选区时，用户改问其他地点、无关问题或明确取消选区，先单独调用 `map_action(action_type="CLEAR", payload={}, clear_selection=true)`，收到结果后再处理新问题。`clear_selection` 是顶层参数；没有有效选区不重复清除。本轮新框选区域、选区内单站追问及单纯清理标记均不触发取消选区。

## 空间要素查询

- 区域内泛问“有哪些”时，用 `list_spatial_elements` 发现目录，再按返回的 `dataKey` 逐类调用 `query_spatial_element`，不因要素类别不同而跳过查询。逐类汇总实际命中数量和名称；断面测点数量不等于断面条数，按返回属性区分。已明确类别时只查目标类别。
- 区域总览由本 Skill 独立完成；查询命中的全部类别纳入回答，再显式调用 `map_action` 展示实际取得的几何，不追加其他业务流程或专题图。
- `list_spatial_elements` 是类别目录，`get_spatial_element_detail` 是类别字段定义，不是单个要素的详情；具体要素记录使用 `query_spatial_element`。
- 某类别查询失败或不支持所需空间关系时，说明该类未完成查询，不当成不存在，也不改成无范围的属性查询。
- 通用选区查询使用 `query={"element": dataKey, "mode": "spatial", "spatial": selected_area.spatial, "includeGeometry": true}`。普通分布查询优先省略 `fields`，使用服务默认字段；自选 `fields`、`conditions` 或 `orderBy` 时复用当前类别的字段定义，缺少定义才调用 `get_spatial_element_detail(dataKey=类别标识)`。字段名、用途、运算符及枚举值均以实际定义为准，不猜测或套用其他类别的字段。
- 观测站分布、位置、基础详情、名称或类型筛选统一使用 `query_spatial_element`。按目录选择观测站类别，类型筛选通过 `query.conditions` 表达，保留原有区域条件；类型编码以该类别的定义为准。
- 收到字段校验错误时，先核对当前类别的最新字段定义，再据此修正，不猜字段名连续重试。仅返回字段选择有误且默认字段满足需求时可省略 `fields`，不得删除用户要求的过滤、排序或空间条件绕过错误。
- 同阶段互不依赖的查询在同一轮提交；依赖目录、字段定义或前一步结果的调用，等待实际返回后再执行。

## 观测站业务查询

观测站基础记录通过通用查询取得；在线状态和观测数据使用同一个 `spatial_query_service` 的以下操作。空间属性状态不等于实时在线状态，空间目录记录不代表观测时序数据；断面调查测点不按业务观测站处理。

| 需求 | `operation`（参数） |
| --- | --- |
| 在线状态 | `station_status`（`tznos`） |
| 位置、基础信息或详情 | `query_spatial_element`（`query`，按真实标识过滤） |
| 最新观测 | `observation_summary`（`tzno`） |
| 最近若干小时的要素变化 | `observation_trend`（`tzno`、`element`、`hours`） |
| 明确起止时间内的观测 | `observation_range`（`tzno`、`data_type`、`start_time`、`end_time`） |

- 已有可信且对应当前目标的 `tzno` 时直接查询观测。只有站名时，按当前类别的字段定义通过 `query_spatial_element` 过滤名称并取得真实站号；独立站名查找可用属性查询，无需构造全球范围。选区内追问保留空间条件；内部候选不绘图。无匹配说明未找到，多个候选无法唯一确定时请用户明确，不任取首项。
- 保留用户指定的时间和指标。相对小时趋势直接用 `hours`；“昨天”等日期需换算且缺少可靠当前时间时，先调用 `CurrentServerTime`，按返回时区解释。`data_type` 不能当作趋势 `element` 的通用别名。
- 当前不支持跨站批量比较或排名最新观测值，不编造操作或逐站拉取绕过限制；地图比较动作与站点位置不能作为观测值比较的依据。

## 地图联动

- “杭州湾有哪些观测站点”等地点或选区查询默认同时需要文字回答和地图展示，无需用户另说“标点”。通用查询设置 `query.includeGeometry=true`，取得真实结果后调用 `map_action`：点位使用 `MARKER_ADD`，线面使用 `GEOJSON_ADD`，再完成回答。用户明确只要文字或仅为内部候选查找时不绘图；缺少有效坐标时说明限制，不编造点位。
- 站点 `markers` 保留真实 `id`、`name`、`coordinates` 和已有的 `type`、`status`；业务观测站有真实站号时以站号作为 `id`。由助手根据查询结果组装每个站点的 `popup_content={"title":站点名称,"fields":[{"label":字段名称,"value":真实字段值}]}`，保留已有的站号、类型、所属区域、管理单位等详情，不省略弹窗或编造缺失信息。查询工具不会自动生成弹窗。
- 通用查询每次只返回一页。需要完整结果时，保持类别、范围、过滤及稳定排序，通过 `query.limit`、`query.offset` 补取；下一页偏移为当前偏移加本页 `returned`。返回零条或分页结果异常时停止并说明未取全。合并同一图层已取得的点位后提交，避免分页绘制覆盖已有点位。
- 业务观测站使用 `layer_id="observation-stations"`，属于同一图层的不同类别结果合并提交；其他要素按稳定类别标识分层。保留其他图层和有效选区，有选区时 `fit_bounds=false`。查询成功为空时可清除对应图层，失败时保留已有结果。
- 已有数据库等工具返回的真实点位或几何可直接调用 `map_action` 展示，无需重复查询。位置和弹窗信息均未变化的已展示对象无需重复绘制；缺少弹窗时用相同真实标识补齐。单站追问复用真实坐标，缺少时用通用查询按真实站号获取；不按站号或返回顺序自行连线。
- 定位、表格、弹窗等额外展示使用 `map_action`。局部清除仅指定目标图层，不取消选区；`FLY_TO` 会清除旧观测站和定位标记，需要切换视角时应在新结果标点前执行，没有可信坐标时不编造定位。

## 结果解释

- 通用查询返回 GeoJSON FeatureCollection，按目录中文名、`total`、`returned` 和实际 `features.properties` 汇总；几何取自 `features.geometry`。不同目录可能重叠，不将数量相加作为去重总数，也不把本页分类计数当作全部记录的分类统计。
- `total` 表示总匹配数，`returned` 表示本页返回数。根据实际取回记录、有效几何和已提交的地图指令说明覆盖范围；未取全、缺少几何或查询失败时说明限制，不把部分结果称为全部。
- 查询成功不等于地图展示；只有调用 `map_action` 后才能说明已提交展示指令。工具回执不代表前端渲染完成，不声称已显示全部结果。
- 仅成功查询的 `total=0` 表示无匹配；失败、未查或截断不等于不存在。空结果不自动放宽范围、类型或时间；失败只在参数可据已有信息纠正时重试，不擅换业务数据源。
- 在线状态与观测新鲜度分开解释，说明观测时间，“最新”不等于实时。趋势和区间数据有采样或条数限制时说明覆盖范围；缺失值不补零。数据可用但坐标缺失时回答已有数据，不承诺已定位。
