# 断面业务

用户提问涉及断面专题分析可展示的要素时，必须调用 `dm_duanmian_analysis` 联动左侧专题分析；需要实测数值、统计或基于观测数据的分析结论时，同时使用 `database_query` 获取回答依据。

## 路由边界

- 调查断面及其站位、辅助点的历史数据、跨期统计和描述性评价，使用 `database_query` 获取数据；涉及可展示要素时还必须按下述规则调用 `dm_duanmian_analysis`，不能只返回文字或表格。
- 地图选区中的业务观测站，以及明确站名的状态、详情、最新观测、趋势或时间区间数据，使用 `observation_service`。
- 断面业务信息、报告、制度和其他非结构化资料，使用 `rag_search`，使用标签：`断面`优先查询相关文档。
- 用户同时要求断面实测数据和非结构化信息依据时，分别调用 `database_query` 与 `rag_search` 后综合回答；涉及可展示要素时仍需联动专题分析。

## 要素提问自动联动专题分析

### 触发与调用顺序

- 以本轮提问及其有效上下文识别要素，不以“出图”“展示”“打开浮层”等词作为调用前提。查询数值、比较、评价、解释相关要素，以及“盐度呢”“同月 E2 呢”等追问，只要涉及可展示要素，都要在本轮实际调用 `dm_duanmian_analysis`；上一轮已打开面板不能替代本轮联动。
- 下文海水化学和水文气象要素是识别范围；“温盐”“T-S”“DO”“营养盐”“水质”“各类要素”“全部要素”等组合、别名或概括性表述也要识别。断面背景下不能因用户没有逐项列出指标或断面编号而漏掉调用。明确属于其他业务观测站或无关语境的同名词按原路由处理，不切换成断面查询；用户本轮明确要求不要展示时尊重该要求。
- 先根据已有条件发送专题分析指令，再按回答所需查询数据库或资料，不等待数据库分析完成才决定是否联动。仅请求展示时无需为出图额外查询数据库；需要数值、比较或结论时不能以专题工具回执代替 `database_query`。纯站位、船舶、经纬度等基础信息查询，或不涉及要素的文档查询，不强行选择要素出图。
- 使用 `dm_duanmian_analysis` 发送专题展示指令，不使用 `map_action` 代替，也不编造前端事件。数据库无数据或失败不改变已识别的展示需求；专题工具失败时如实说明展示指令未完成，有可纠正的参数才修正重试。
- 用户询问或数据库查询结果涉及专题工具支持的分析类型、参数或图例时，也按对应主题联动；已有相同参数的本轮调用不重复发送。
- 工具负责发送展示指令，前端负责查询和绘图：传入有效 `voyage` 会触发前端按参数查询出图；省略 `voyage` 只打开面板。实际出图还取决于前端参数匹配、查询成功及有可用数据，不能把工具参数校验通过当成出图成功。

### 分析类型选择

`analysis` 必填。用户明确指定的、与要素匹配的受支持图表类型优先；否则优先匹配表层、垂向、要素关系等分析意图，再按要素默认类型选择，不因用户未指定图表类型而追问或跳过展示。类型和参数格式以当前工具 Schema 为准。

| 提问涉及的要素或分析意图 | `analysis` 与要素类型 |
| --- | --- |
| 表层、表面或表层沿程变化 | `surface`；按要素选择 `chemistry` 或 `hydromet` |
| 单要素随水深变化、垂向曲线 | `depth-curve`，按要素选择 `elementType`；溶解氧优先 `do-profile` |
| 温盐关系、T-S 点聚图、水团识别 | `ts-scatter`；省略 `section`、`elementType`、`element` |
| 营养盐、活性磷酸盐、活性硅酸盐、亚硝酸盐、硝酸盐、氨氮及其结构 | `nutrient`；省略 `elementType`、`element` |
| 溶解氧、DO、缺氧相关分析 | `do-profile`；省略 `elementType`、`element` |
| 海水温度、盐度、pH、总碱度，未指定上述分析意图 | `temp-section`，可传化学要素 `element`，省略 `elementType`；后端固定为 `chemistry`，不限于温度 |
| 气温、风速、气压、波高等水文气象要素，未指定图表类型 | `surface`，`elementType="hydromet"`；不能使用固定为海水化学的 `temp-section` |
| 水质、各类要素、全部要素或笼统断面分析，尚无具体要素 | 先用 `temp-section` 打开化学要素剖面入口；明确只问水文气象时用 `surface`、`hydromet`。均省略 `element` 和 `voyage`，待选定要素后出图，不能让默认要素图冒充全部要素分析 |

- 多个明确要素能由同一专题覆盖时合并展示，例如温盐关系用 `ts-scatter`、多项营养盐结构用 `nutrient`。只要求分别比较温度和盐度时，分别按要素展示，不擅自改成水团分析。
- 无法由同一专题覆盖的明确要素、多个 E1/E2/E3 断面或多个明确航次，按所需组合分别调用；每次参数只传单个值，不能拼接名称、传数组或新增批量参数。相同参数在本轮不重复发送。多个调用可能依次切换同一面板，不能保证各张图保留或并排展示；跨要素、断面或航次的比较结论仍由数据库结果支撑。
- 概括性“全部要素”先联动上述入口，数据库查询仍须按后文覆盖完整指标范围；不得声称默认专题已覆盖全部要素。仅涉及能力边界中不支持的要素时说明限制，不用相近要素冒充；混合请求仍展示其中支持的部分。

### 参数与范围

- `section` 只接受 `E1`、`E2`、`E3`，可从明确的断面站位（如 `E1001`、`E1-001`）识别所属断面；未指定则省略，不能默认指定 E1。`ts-scatter` 固定合并全部断面，不传 `section`，也不能将它描述为单断面结果。
- `voyage` 只接受有效航次年月 `yyyy-MM`。只传用户指定或当前话题上下文明确的航次月份；精确日期作为航次指代时可取所属年月，但不能把整月图称为当天数据，精确日期查询仍交给数据库。追问可继承同一目标的明确航次；用户切换时间或对象后，不沿用不适用的旧条件。不能用当前日期或猜测的“最新航次”补齐，也不能传 `yyyy-MM-dd`。
- 缺少航次也必须先调用工具打开相应专题入口，简短说明需选择航次后查询出图；不把先追问航次作为联动的前置条件。只有年份、季节或连续时间范围时，不任取某月冒充整个范围；省略 `voyage` 打开入口，数据库仍按原时间范围查询。用户明确列出的多个年月可分别传入对应调用。
- `elementType` 仅在 `depth-curve`、`surface` 中按明确类别传入；这两类需要指定 `elementType` 后才能传 `element`。`temp-section` 可直接传化学要素 `element`；`ts-scatter`、`nutrient`、`do-profile` 均省略 `elementType` 和 `element`。
- `element` 必须严格使用当前 Schema 的枚举值，不传物理列名或任意中文短名。海水温度/水温 → `温度 T`，盐度 → `盐度 S`，pH → `酸碱度 pH`，总碱度 → `碱度 A`，DO/溶氧 → `溶解氧`；各营养盐按枚举使用带化学标识的完整名称。只说“温度”且用户和上下文均未限定类型时，分别展示海水温度与气温，数据库也分别查询。
- 数据库字段列表不等于专题可展示要素清单。水文气象专题当前支持气温、风速、气压、相对湿度、能见度、最大波高、有效波高、有效波周期、总云量、低云量、透明度、风向，以 Schema 更新为准；海况、波型、云状、天气现象等未列入枚举的字段仅查询数据库，不冒充可展示要素。混合请求继续展示其中受支持的部分；无法确定用户指的是哪个受支持要素时，打开相应入口并省略 `element`、`voyage`，不使用默认要素图冒充目标。
- 专题参数不支持 EL、EK、辅助点、逐站筛选、指定采样深度或跨期统计口径；这些条件完整保留给 `database_query`，不编造专题参数。明确查询 EL、EK 或辅助点时，省略 `section` 和 `voyage` 只打开对应要素入口，避免自动查询其他断面。查询 E1/E2/E3 的单站或指定深度时可展示所属断面的完整剖面，但必须区分背景图与精确查询结果，不将整断面图称为单站或该深度的筛选结果。

### 调用示例

下表为 `dm_duanmian_analysis` 的工具参数 JSON，示例文本本身不会执行。实际任务必须发起工具调用，不能仅在回答中输出 JSON；示例日期、断面和要素不作为其他问题的默认值。需要实测数据结论时，调用后仍须查询数据库。

| 用户提问及有效上下文 | 工具参数 | 前端预期动作（不代表已成功出图） |
| --- | --- | --- |
| “2025年11月 E1 的盐度怎么样？” | `{"analysis":"temp-section","section":"E1","voyage":"2025-11","element":"盐度 S"}` | 查询该航次盐度剖面并出图 |
| 上文为 E1、2025年11月，本轮“DO 呢？” | `{"analysis":"do-profile","section":"E1","voyage":"2025-11"}` | 查询该航次溶解氧垂向分布并出图 |
| “2025年11月 E2 风速平均多少？” | `{"analysis":"surface","section":"E2","voyage":"2025-11","elementType":"hydromet","element":"风速"}` | 查询风速沿程图；平均值由数据库获取 |
| “2025年11月 E1 盐度随水深怎么变化？” | `{"analysis":"depth-curve","section":"E1","voyage":"2025-11","elementType":"chemistry","element":"盐度 S"}` | 查询盐度沿水深曲线并出图 |
| “2025年11月各断面的温盐关系如何？” | `{"analysis":"ts-scatter","voyage":"2025-11"}` | 合并全部断面查询 T-S 点聚图 |
| “看看 E3 营养盐情况”，无可继承航次 | `{"analysis":"nutrient","section":"E3"}` | 仅打开营养盐专题，待选择航次 |
| “对比2024年和2025年各类要素” | `{"analysis":"temp-section"}` | 仅打开剖面入口；完整跨年比较由数据库完成 |
| “2025年11月 EL 盐度如何？” | `{"analysis":"temp-section","element":"盐度 S"}` | 仅打开入口，说明面板支持 E1/E2/E3；EL 数值由数据库获取 |

## 断面与数据范围

- 当前东海共布设5条断面（E1、E2、E3、EL、EK）及4个辅助点。
- 主要的 E1、E2、E3 三条断面包含26个站位。库内这些站位同时有紧凑式和连字符式编码，例如 `E1001` 与 `E1-001`为同一站点不同时期的命名；去掉连字符后可归为 26 组：E1 的 001–007、E2 的 001–011、E3 的 001–008。每组两种存储形式对应不同内部 ID。用户倾向于使用`E1001`样式，除非明确要求精确存储编码，应在业务问题中统一使用`E1001`样式。
- 库内非 E1/E2/E3/EL/EK 站位编码包括 `A`、`B`、`C`、`D` 四个辅助点和 91 个纯数字历史编码站点。
- 海水化学观测指标为：海水温度、盐度、pH、溶解氧、活性磷酸盐、活性硅酸盐、亚硝酸盐、硝酸盐、氨氮、总碱度。
- 水文气象观测内容为：气温、风速、风向、气压、相对湿度、能见度、海况、波型、最大波高、最大波周期、波级、海发光类型、海发光强度、风浪、涌浪、有效波高、有效波周期、总云量、低云量、低云高、云状、天气现象、水色、透明度、水深。
- 基础信息为：观测日期、站位名称和编号、船舶名称和编号、经度、纬度；海水化学记录还包含采样层次。
- 当前数据画像中指标历史覆盖差异很大，pH 和营养盐字段尤其稀疏；请求统计时应同时获取各指标有效样本数，不用总记录数代替。

## 组织业务问题

查询数据库时，不要自行编写 SQL、猜测字段名或描述数据库结构；把用户的业务条件整理成完整、明确的自然语言问题。传给 `database_query` 的 `question` 应完整保留用户指定的断面或站位、时间范围、采样深度、统计口径、排序、分组和明细要求；全部批次合计必须覆盖用户要求的指标。

- 仅给出历史年月并询问“各类要素”或“全部要素”、没有指定对象时，按5条全部断面站位处理，不追问断面编号。
- 未要求“各站”或“逐站”时，按指定范围整体统计，不擅自拆成逐站结果。
- 用户只说“温度”且用户和上下文均未限定类型时，请求分别查询海水温度和气温，不要混合统计。
- 用户要求水质评价但没有提供评价标准时，采用断面数据库已有海水化学指标数据并做描述性分析；不要要求数据库工具判定水质等级或是否达标。
- 除上述默认口径外，存在会实质改变查询结果的歧义时，先请用户明确。
- 除非用户明确要求逐行明细，所有查询都必须严格控制结果行数
- 不得通过只取前若干行代替完整范围统计。

## 分批查询

用户询问各类要素或没指明要素时，在轮次充足时按表、要素组或时期拆批，保持条件和统计口径一致，但是最多也不要超过 4 批；仅剩 1～2 轮可查询时，尽量合并剩余需求并在当轮查齐。保留成功结果，仅补查缺项，最后统一汇总。

## 回答要求

- 按触发规则需要联动时，最终回答前确认本轮已实际调用专题工具，不能用“可以展示”“建议打开”等文字替代调用。成功回执只表示展示指令已发送，不证明左侧已渲染、已有数据或分析完成；分析结论只能依据数据库或资料工具的真实结果。
- 数据分析先说明数据范围和有效样本覆盖，再给出主要统计、比较或描述性结论；专题出图只说明工具回执确认的动作。
- `truncated=true` 时优先请求完整范围的聚合统计，或在剩余批次内按互不重叠的条件补查；无法补全时明确结果覆盖范围与不足，不把部分结果当成完整结论，也不无限重试。
- 空结果应如实说明并建议核对条件，不得自行放宽范围重新查询。
- 海水温度与气温必须分别表述；缺失值不得解释为 0。

## 能力边界

- 当前数据只有观测日期，没有观测时分秒，此限制针对断面数据库。
- 断面数据库当前不包含水质等级标准，也不包含湿球温度、绝对湿度、波速、明确波向、波长、声速或断面报告字段。
- 专题出图支持的断面、分析类型及参数以 `dm_duanmian_analysis` Schema 为准，不因本 Skill 涵盖 EL、EK 等对象就向出图工具传入不支持的值。
- 工具没有返回的数据不得推断或编造。
