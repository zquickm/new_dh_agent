# 断面数据 AI SQL 查询指南

表名、字段、类型、单位和键以 DDL 为准。本指南只补充 DDL 无法表达的业务语义和查询规则。

## 站位与表关系

- 只使用断面化学表和断面水文表；站位信息已内嵌在这两张表中，不要关联其他站位表。
- `station_name` 已补全，存放 `E1005`、`E2008`、`E3006` 等业务站位编码；`station_id` 是与 `station_name` 对应的数字站点 ID。用户指定业务站名时使用 `station_name`，明确指定数字 ID 时可使用 `station_id`。
- E1/E2/E3 代表 3 个断面，`E1001` 表示 E1 断面的一个站点。E1/E2/E3 分别用 `UPPER(TRIM(station_name)) LIKE 'E1%'`、`'E2%'`、`'E3%'` 过滤；具体站位使用清理后的 `station_name` 精确匹配。
- 数据中还有不属于 E1/E2/E3 断面的辅助站位 `A`、`B`、`C`、`D`，原始资料也可能写作小写 `a`、`b`、`c`、`d`；另有其他历史站点。除非用户明确指定，默认断面查询只纳入以 E1、E2 或 E3 开头的站位。
- 化学表和水文表独立查询、各自聚合；除非另有已验证的关系，不得按 `station_id`、`station_name` 或日期直接连接原始观测行。

## 数据语义

- 化学表的 `depth_m` 表示采样层次；业务资料中有表层、具体米数层和底层等表达。水文表的 `depth_m` 在 DDL 中表示水深，是否与化学表采样层次同义尚未确认，不得用它直接对齐两表记录。
- 两表的 `depth_m` 都是文本列，实际数据多为数字形式，但水文表存在 `＞1000` 这类非数字值。仅在深度范围、数值排序或统计时，先排除非数字值再转换；精确查询优先按清理后的文本值匹配。
- 数据治理后不再使用空字符串表示缺失，缺失值以 `NULL` 表示；不得把 `NULL` 转成 0 参与统计。
- 水文表中 `sea_state`、`wave_type`、`wave_level`、`sea_glow_type`、`sea_glow_intensity`、`water_color` 是类别值；即使内容看起来是数字，也不得转数值后求平均或求和。
- `sea_state` 存放海况等级，但 0～7 对应的文字定义尚未确认。`wave_type` 存放海浪类型，业务资料存在“混合浪”等表述，但 `U/F`、`F/U`、`UF`、`FU`、`U`、`F` 与中文类型的映射尚未确认，不得自行翻译或合并。
- `sea_glow_type` 存在乱码和组合值，`sea_glow_intensity` 存在逗号组合值及字母值，`water_color` 存在带空格或疑似拼接的编码；获得业务字典和清洗规则前不得拆分、纠错、翻译或转数值。
- `wind_wave` 和 `swell` 的样例为数字形式文本，但业务含义和单位未确认；保持文本语义，不擅自解释或数值聚合。
- `wind_direction_deg` 是环形角度，不得使用普通 `AVG`；用户查询主导风向时，应按方位区间计数。
- `total_cloud` 和 `low_cloud` 的 DDL 单位标为百分比，但实际值域疑似采用 0～10 的云量成数；标准确认前保持原值，不乘以 10、不添加百分号，也不按百分比解释。
- “水温”指化学表的 `temperature_c`，“气温/干球温度”指水文表的 `air_temperature_c`；只说“温度”时同时查询两者并标明类型。
- `alkalinity_mmol_dm3` 的业务名称是总碱度；用户所说“碱度”或“总碱度”都查询该字段。
- 数据库不包含水质等级标准。未提供外部标准时，只能描述指标统计和变化，不得判定国家水质等级。

## 默认查询口径

- “断面数据”、“各类要素”或“全部要素”默认同时查询化学和水文两张表。
- 未要求“各站”或“逐站”时，整体分析不按站位分组。
- “各类/全部要素”未指定口径时，数值测量字段只计算 `AVG`，每张表每个时期同时返回 `COUNT(*) AS record_count`；类别字段不做数值聚合，紧凑返回去重值集合。只有用户明确要求类别分布时，才按类别分组计数。
