# 断面数据 AI SQL 查询指南

表名、字段、类型、单位和物理键以 DDL 为准。本指南只补充会影响 SQL 正确性的业务语义和查询规则。

## 表、站位与记录粒度

- 只使用断面化学表和断面水文表；站位信息已内嵌，不关联其他站位表。用户指定站位编码时查 `station_name`，只有明确指定数字 ID 时才查 `station_id`。
- 断面包括 E1、E2、E3、EL、EK。整条断面按对应编码前缀过滤，如 `UPPER(TRIM(station_name)) LIKE 'E1%'`；仅给出历史年月并询问“各类要素”或“全部要素”、没有指定对象时，默认查询这五条断面。
- 任何涉及早年历史数据，必须考虑历史数字编码站点。比如涉及断面最早数据年份，不能只查询五条断面。
- E 系列编码存在紧凑式和连字符式，如 `E1001` 与 `E1-001`，两者对应不同 `station_id`。查询业务站位时默认同时匹配两种形式：`REPLACE(UPPER(TRIM(station_name)), '-', '') = 'E1001'`；只有用户明确要求原始存储编码时才精确匹配。
- 水文表由 `station_id + observed_at` 组成业务唯一键，`depth_m` 是水深属性。化学表的当前业务粒度为 `station_id + observed_at + depth_m`，同站同日可有多个采样层次。
- 记录级关联只能使用 `station_id + observed_at`，关系是“一条水文记录对应多条化学记录”。关联后水文值会重复，不得直接聚合；跨表统计应先分表聚合，再合并结果。

## 字段语义和数据质量

- 化学表 `depth_m` 是采样层次，水文表 `depth_m` 是水深，不得用它们对齐两表记录。两列均为文本；水文数据含空字符串和 `＞1000` 这类非数字值，只有先验证格式才能转数值。
- 按 DDL 字段类型处理缺失值；缺失值不得转成 0 参与统计。
- `sea_state`、`wave_type`、`wave_level`、`sea_glow_type`、`sea_glow_intensity`、`water_color`、`wind_wave`、`swell`、`weather_phenomena` 和 `cloud_form` 都保持原始类别或文本语义；获得业务字典前不转数值、不拆分、不翻译、不自行合并。
- `wind_direction_deg` 是环形角度，不使用普通 `AVG`；主导风向应按方位区间计数。
- `total_cloud` 和 `low_cloud` 的 DDL 单位与实际值域疑似不一致；保持原值，不乘以 10，不按百分比解释。
- “水温”查化学表 `temperature_c`，“气温/干球温度”查水文表 `air_temperature_c`；只说“温度”时分别查询并标明类型。`alkalinity_mmol_dm3` 是总碱度。
- 数据库不含水质等级标准；未提供外部标准时只做描述性分析，不判定等级或达标情况。

## 默认查询规则

- 完整保留用户的日期、断面、站位、深度、指标、分组和统计口径。月份使用左闭右开的完整自然月区间。
- “断面数据”、“各类要素”或“全部要素”默认查两张表；未要求“各站/逐站”时按整体统计。
- 除非用户明确要求逐行明细，所有查询都必须在在数据库内聚合，仅返回回答所需的最少分组和统计列，严格控制结果行数；不得拉取原始行交给上层计算，也不得用 LIMIT 取部分数据代替完整范围统计。
- 数值指标默认返回 `AVG(field)` 和对应的 `COUNT(field)` 有效样本数，每表每时期另返回 `COUNT(*) AS record_count`；只有用户明确要求时才增加极值。
- 类别字段默认返回紧凑的去重原始值；只有明确询问分布时才分组计数。
- 在完整满足本次问题和统计口径的前提下，优先生成简短 SQL，直接返回所需统计列，避免不必要的 CTE、跨表拼接和 `JSON_OBJECT` 包装。
